# SEO 自动标签

> 写文章时自动分析正文，按 SEO 思路生成候选标签，**由你勾选决定是否采用**。

一个 WordPress 插件。点一下按钮，它读当前文章内容，给出候选标签；
每个标签带勾选框，**你不点「应用」，一个字都不会写进文章**。

作者：[西瓜烧鱼](https://www.rrshare.com/) · 许可：GPL-2.0-or-later

## 特性

- **编辑器右侧面板** —— 兼容区块编辑器（Gutenberg）与经典编辑器
- **文章列表一键生成** —— 列表页多一列「SEO 标签」，一眼看出哪些文章没打标签，可一键补齐
- **两种生成方式**
  - 本地算法：不联网、不花钱、装上即用
  - AI 智能：填一个 OpenAI 兼容接口的 API Key，让大模型按 SEO 价值选词
- **优先复用站内已有标签** —— 避免同一个意思建出一堆标签（对 SEO 更友好）
- **标签健康度面板** —— 统计没打标签的文章、没被使用的标签、只用过 1 次的标签
- **标签数量提醒** —— 一篇文章超过 8 个标签时提示可能稀释权重
- **AI 结果缓存** —— 同一篇文章内容不变时重复点生成不再花钱
- **调用限速** —— 防止有人刷爆你的 API 额度
- **失败会说明原因** —— Key 无效 / 余额不足 / 被限流 / 地址写错，都直接告诉你
- **标签屏蔽词** —— 写进黑名单的词永远不会被推荐

## 为什么标签要控制数量

WordPress 的每个标签都会生成一个归档页。标签建得太多太碎，会：

- 产出大量内容稀薄的页面，**稀释整站权重**
- 让同一个意思被拆成多个标签（「PS教程」和「Photoshop教程」），互相分权

所以本插件默认只给 5 个候选，并且默认优先复用已有标签。

## 安装

1. 下载本仓库的 `seo-auto-tags.zip`，或把整个目录打包成同名 zip
2. WordPress 后台 → **插件 → 安装插件 → 上传插件** → 选择 zip → 现在安装
3. 启用插件
4. 进入 **设置 → SEO 自动标签** 按需配置

要求：WordPress 5.8+、PHP 7.4+（建议 PHP 8.0 以上）。

> 也可以直接把 `seo-auto-tags` 目录上传到 `wp-content/plugins/` 下再启用。

## 使用

**写文章时：**

1. 编辑页右侧找到「SEO 自动标签」面板
2. 点「生成标签」
3. 取消勾选不想要的
4. 点「应用选中标签」→ 保存文章

**给旧文章补标签：**

到「文章」列表页，找到「SEO 标签」列里显示「未打标签」的行，点「一键生成」，
确认弹窗里列出的标签后自动追加（**不会删掉原有标签**）。

## 配置 AI 模式

选「AI 智能」后填三样：服务商、API Key、模型名。接口地址和模型名选服务商时会自动填好。

内置预置：

| 服务商 | 说明 |
|---|---|
| DeepSeek | 中文好、价格极低，**推荐** |
| 通义千问 | 阿里云，新用户有免费额度 |
| 智谱 GLM | 有免费模型（glm-4-flash） |
| 月之暗面 Kimi | 长文本能力强 |
| OpenAI | 需要国外网络环境 |
| 自定义 | 任何 OpenAI 兼容接口（必须 https） |

填好后点「测试连接」确认能通，再去文章里用。

### AI 兼容性

不同服务商的返回格式不完全一样，插件按常见格式逐个兜底：

- 标准 OpenAI 兼容：`choices[0].message.content`
- 老式 completions：`choices[0].text`
- 多模态数组：`message.content[0].text`
- 部分网关：`output.text` / `content`
- 网关强制返回 SSE 分块时，自动拼接

出错时会把 HTTP 状态码翻译成能照着修的建议：

| 状态码 | 提示 |
|---|---|
| 401 | API Key 无效或已过期，重新复制粘贴一次 |
| 402 | 账户余额不足，去服务商后台充值 |
| 404 | 接口地址不对，多数服务商要求以 `/v1` 结尾 |
| 429 | 被服务商限流了，等一会儿再试 |
| 超时 | 服务器可能出不了外网，或模型响应太慢 |

报错信息里的 API Key 会被自动脱敏。

## AI 消耗说明

会真实调用接口的地方只有四处：

| 触发点 | 消耗 | 防护 |
|---|---|---|
| 编辑器点「生成标签」 | 一次调用 | 限速 + 缓存 |
| 打开编辑器自动生成（可选，默认关） | 同上 | 同上 |
| 文章列表页「一键生成」 | 每篇一次 | 限速 |
| 设置页「测试连接」 | 约 20 token | 一分钟最多 5 次 |

**发送量控制**：正文做「头 + 尾」采样，控制在 4000 字以内（约 2400 token），
单次调用成本约几厘钱。想更省就把「结果缓存」开着。

达到限速上限时**自动改用本地算法**并在界面上说明原因，不会报错中断，也不会偷偷继续花钱。

> 想彻底不花钱：生成方式选「本地算法」—— 不联网、不调用任何接口。

## 安全

| 项 | 做法 |
|---|---|
| CSRF | 所有 AJAX 接口校验 nonce |
| 越权 | 逐个校验当前用户对目标文章的编辑权限 |
| SSRF | AI 接口地址强制 https，禁止指向本机 / 内网 / 云元数据地址；保存与测试时还会做 DNS 解析检查 |
| API Key 泄露 | 强制 https 传输；设置页不回显完整 Key；报错信息自动脱敏 |
| 额度被刷 | 按用户按小时限速 |
| 批量滥用 | 单次最多创建 12 个标签 |
| XSS | 前端一律用 `textContent` 写入 |
| 内存耗尽 | 超长正文按段落均匀采样，压到 3 万字以内再分析 |
| 进程占满 | 接口超时 25 秒，避免慢请求拖死小内存机器的 PHP 进程池 |

## 开发

代码不依赖任何构建步骤 —— 纯 PHP + 原生 JavaScript，克隆下来直接就能改。

本地测试建议用便携版 PHP：

```bash
# Windows
curl -sSL -o php.zip https://windows.php.net/downloads/releases/latest/php-8.3-nts-Win32-vs16-x64-latest.zip
```

`php.ini` 里需要启用 `mbstring`（否则中文长度判断会失准）。
